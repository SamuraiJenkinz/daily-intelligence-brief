# Plan 01-05: Manual Trigger Endpoint

**Phase**: 01 — Vertical Slice Foundation
**Depends on**: 01-01 (FastAPI app), 01-02 (collector), 01-03 (classifier), 01-04 (reporter)
**Required by**: Phase 1 success criteria (manual trigger capability)

## Goal
Create FastAPI endpoint to manually trigger complete pipeline (collection → classification → report generation) and view HTML output in browser, proving end-to-end vertical slice functionality.

## Tasks

### Task 1: Create Admin Router with Manual Trigger Endpoint
**File**: `C:\BrasilIntel\MDInsights\app\routers\admin.py`
**Action**: Create
**Details**:
- Admin router with prefix `/admin`
- POST endpoint `/admin/trigger-pipeline` accepting optional query param `role` (default: "Brokers")
- Endpoint orchestrates: (1) Collection via ApifyCollector, (2) Classification via RoleClassificationService, (3) Report generation via RoleReportService
- Create Run record with status="running" at start
- Execute collection: `collector.collect_from_sources()` → stores articles in database with run_id
- Execute classification: `classifier.classify_articles(articles)` → updates articles with roles, priority, summary, sentiment
- Execute report generation: `reporter.generate_role_brief(target_role=role, articles=classified_articles)` → returns HTML string
- Update Run record with status="completed", articles_collected count, articles_classified count
- Return HTMLResponse with generated report HTML (renders in browser)
- Error handling: If any step fails, update Run status="failed" with error_message, return 500 with error details
- Pattern: Similar to BrasilIntel run trigger endpoints, orchestrating multiple services

### Task 2: Implement Pipeline Orchestration Service
**File**: `C:\BrasilIntel\MDInsights\app\services\pipeline.py`
**Action**: Create
**Details**:
- PipelineOrchestrator class coordinating collection → classification → reporting
- Constructor dependencies: ApifyCollector, RoleClassificationService, RoleReportService, database session
- Method `run_full_pipeline(role: str = "Brokers") -> dict` executing all steps and returning results
- Create Run record, track progress through each step
- Return dict with: run_id, articles_collected, articles_classified, html_output (for specified role), status, error (if failed)
- Structured logging: Log each pipeline step start/completion, article counts, timing metrics
- Transaction management: Commit after each major step (collection, classification) for progress visibility
- Pattern: Pipeline orchestration with error recovery and detailed logging

Admin UI is minimal HTML form. Main complexity is ensuring proper transaction management and error recovery.

## Notes
- **Pipeline execution time:** Phase 1 with 20 articles ~1-2 minutes (Apify scraping 10-30s, Azure OpenAI classification 30-60s, report generation <1s). Browser should show loading state during execution.
- **Error scenarios to test:** (1) Apify scraping fails → status="failed", articles_collected=0, (2) Azure OpenAI rate limit → partial classification, (3) Database locked → transaction retry logic.
- **Future enhancements:** Phase 5 adds email delivery step to pipeline. Phase 6 adds scheduler for automated daily execution. Phase 7 adds monitoring and alerting. Phase 1 proves the basic orchestration pattern.
- **Security consideration:** Phase 1 has no authentication on admin endpoints (acceptable for localhost testing). Phase 6 admin dashboard adds proper authentication (username/password from config).
- **Testing workflow:** (1) Run test_pipeline.py to validate orchestration, (2) Start FastAPI server with `uvicorn app.main:app --reload`, (3) Open browser to http://localhost:8000/admin/trigger, (4) Submit form and verify report displays, (5) Check `/admin/runs` for execution history.
- **Success validation:** Phase 1 complete when user can visit `/admin/trigger`, click button, wait 1-2 minutes, and see fully-rendered HTML report with 10-20 articles distributed across role tabs based on classification.

### Task 3: Implement Template Filters and Context
**File**: `C:\BrasilIntel\MDInsights\app\templates\role_brief.html` (Jinja2 logic)
**Action**: Modify (add Jinja2 filters)
**Details**:
- Jinja2 loop over roles: `{% for role in ["Brokers", "Leadership", "Compliance", "Underwriting"] %}`
- Within each role section, filter articles: `{% for article in articles if role in article.roles %}`
- Group by priority: Nested loop over priorities ["Critical", "High", "Medium", "Monitor"], filter articles matching both role AND priority
- Display article count per priority section: `{{ priority_articles|length }}`
- Format dates: `article.published_at.strftime('%b %d, %Y') if article.published_at else 'Recent'`
- Capitalize sentiment: `article.sentiment|capitalize`
- Pattern: Standard Jinja2 filtering, similar to research template example

## Notes
- **Tab implementation rationale:** Phase 1 output is served via FastAPI endpoint and viewed in browser. JavaScript tabs work perfectly in this context. Phase 5 email delivery will handle email client limitations by generating separate emails per role (no tabs needed in email).
- **Prototype reference:** `C:\BrasilIntel\RefChyt\prototype_daily_intelligence_brief.html` contains Marsh branding CSS, header structure, story card design. Copy header gradient, typography, color palette exactly. Simplify by removing market pulse bar, sector heatmap (Phase 4 features).
- **Multi-role article handling:** A single article tagged with ["Brokers", "Leadership"] appears in BOTH tabs. Template logic must filter articles per tab, not move them.
- **Priority grouping UX:** Within each role tab, articles are grouped by priority (Critical first, Monitor last). This provides visual hierarchy and helps users focus on most important items first.
- **CSS inlining timing:** premailer inlines CSS during report generation, preparing HTML for future email delivery. For Phase 1 browser viewing, inlining is optional but included for Phase 5 compatibility.
- **Testing workflow:** Generate test report → Open in Chrome/Edge → Click through all tabs → Verify filtering works → Check responsive design (browser DevTools mobile view) → Inspect HTML source to confirm CSS inlined.
- **Phase 2 compatibility:** Template is role-agnostic and will work with 18+ sources without modification. Phase 4 will enhance template with executive summaries, sector heatmaps, entity trackers.

Create `scripts/test_advanced_classification.py` modeled on the existing `scripts/test_classification.py` pattern but testing all Phase 3 fields.

The script should:

1. **Setup** (same pattern as test_classification.py):
   - Add project root to sys.path
   - Import from app.database (SessionLocal, init_db), app.config (get_settings), app.models, app.services.classifier
   - Import `json`, `sys`, `subprocess` from stdlib
   - Validate Azure OpenAI configuration, exit with message if not configured
   - Initialize database

2. **Run migration as subprocess at script start** (ensures columns exist before any queries):
   ```python
   subprocess.run([sys.executable, "scripts/migrate_003_classification_fields.py"], cwd=project_root, check=True)
   ```
   This is the ONLY approach to use. Do NOT use exec(open(...)), do NOT import the migration module, do NOT trust it was already run. The subprocess approach is simple, reliable, and idempotent (the migration handles "already exists" gracefully).

3. **Reset classification for test articles**:
   - Query 5 articles from the latest run (ordered by created_at desc)
   - Set their `roles = None` to force re-classification (the classifier skips articles with roles already set)
   - Commit the reset
   - Print which articles will be re-classified

4. **Classify with expanded schema**:
   - Create RoleClassificationService with settings
   - Call `classifier.classify_articles(db, articles)` on the 5 reset articles
   - This will use the expanded prompt and store all 9 fields

5. **Display comprehensive results**:
   For each classified article, print:
   - Title (truncated to 70 chars)
   - Source name
   - Roles (parsed from JSON), Priority, Sentiment (existing fields)
   - Impact Level (new)
   - Category (new)
   - Region (new)
   - Business Line (new)
   - Entities (new): Parse entities from JSON string with `json.loads(article.entities)` to get a list of dicts, then iterate to display each entity as `"  - {entity['name']} ({entity['type']}): {entity['context']}"`. Handle the case where `article.entities` is None or empty string by displaying "No entities extracted" as a warning.

6. **Entity JSON round-trip validation**:
   For each classified article, verify the entity JSON round-trip explicitly:
   ```python
   entities = json.loads(article.entities)
   for entity in entities:
       assert "name" in entity, f"Entity missing 'name': {entity}"
       assert "type" in entity, f"Entity missing 'type': {entity}"
       assert "context" in entity, f"Entity missing 'context': {entity}"
       assert entity["type"] in ("company", "person", "organization"), f"Invalid entity type: {entity['type']}"
   ```
   Print entity round-trip validation result (PASS/FAIL) per article.

7. **Validation metrics**:
   - Multi-role assignment rate (target: 40-60%)
   - Average entity count per article (target: 3-10)
   - Impact level distribution (count per level)
   - Category distribution (count per category)
   - Region distribution
   - Business line distribution
   - Flag any articles with 0 entities as warnings
   - Flag any NULL new fields as errors

8. **Summary verdict**:
   - Print PASS if: all 5 articles have non-NULL values for all 9 fields AND average entity count >= 3 AND all entity round-trips valid
   - Print FAIL with specific failures otherwise

Follow the existing test script conventions:
- Use emoji prefixes for status messages

- Use `if __name__ == "__main__":` block
- Handle exceptions with traceback printing
- Close database session in finally block

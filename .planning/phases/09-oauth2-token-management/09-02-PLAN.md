    **Changes to PipelineOrchestrator:**

    1. **Add import**: `from app.auth.token_manager import TokenManager`

    2. **Update `__init__` signature** to accept an optional `token_manager: Optional[TokenManager] = None` parameter. Store as `self.token_manager`. This keeps backward compatibility — callers that don't pass it get None (v1.0 behavior preserved).

    3. **Add auth step in `run_full_pipeline_with_email`** — insert a new "Step 0: Authenticate" BEFORE Step 1 (collection). This step runs early so the degraded-auth flag is known before any API calls:

       ```python
       # Step 0: Authenticate to MMC Core API
       degraded_auth = True  # Default: degraded (use Graph API fallback)
       if self.token_manager and self.token_manager.is_configured:
           step_start = datetime.utcnow()
           self.logger.info("step_0_auth_started")
           token = await self.token_manager.get_token()
           if token:
               degraded_auth = False
               self.logger.info("step_0_auth_completed", degraded_auth=False)
           else:
               self.logger.warning(
                   "step_0_auth_failed",
                   degraded_auth=True,
                   message="JWT acquisition failed, email will use Graph API fallback"
               )
           step_duration = (datetime.utcnow() - step_start).total_seconds()
           self.logger.info("step_0_auth_duration", duration_seconds=round(step_duration, 2))
       else:
           self.logger.info(
               "step_0_auth_skipped",
               reason="MMC auth not configured" if not self.token_manager else "TokenManager not configured"
           )
       ```

    4. **Store degraded_auth in result dict**: Add `"degraded_auth": degraded_auth` to the result dictionary (both in run_full_pipeline_with_email and run_full_pipeline). This flag will be consumed by Phase 12's enterprise email client to decide delivery method.

    5. **Log degraded_auth in pipeline_summary**: Add `degraded_auth=degraded_auth` to the final `pipeline_summary` log event.

    6. **Do NOT change the email delivery step (Step 8)** — it currently uses GraphEmailService unconditionally. Phase 12 will modify Step 8 to check `degraded_auth` and choose between enterprise email and Graph API. For now, Step 8 continues to use Graph API regardless.

    7. **Also update `run_full_pipeline`** (the non-email variant): Add the same Step 0 auth block for consistency, storing `degraded_auth` in result. Even though this method doesn't send email, having auth status in the result dict is useful for the admin dashboard.

    **Critical rules:**
    - `degraded_auth` defaults to `True` — safe default means Graph API fallback
    - Auth failure must NEVER prevent the pipeline from continuing
    - The `token_manager` parameter is Optional — existing code that doesn't pass it still works
    - No changes to Step 8 email delivery — that is Phase 12's job
    - The step numbering in log events shifts (existing steps become 1-9 instead of 1-8 in email variant, or stay as-is if you prefer to call it step_0). Use step_0 prefix to avoid renumbering existing steps.

     @retry(

5. Add tenacity retry decorator to `app/services/classifier.py`:
   - Decorate `classify_article()` with:
     ```python
     @retry(
         stop=stop_after_attempt(3),
         wait=wait_random_exponential(multiplier=1, min=2, max=15),
         retry=retry_if_exception_type((ConnectionError, TimeoutError)),
         before_sleep=before_sleep_log(logger, logging.WARNING),
         reraise=True
     )
     ```
   - Do NOT retry on all exceptions (API key errors, schema errors should fail fast)
   - Only retry on transient network/timeout errors
   - Import from openai: `APITimeoutError, APIConnectionError` and add to retry_if_exception_type

6. Add tenacity retry decorator to `app/services/emailer.py`:
   - Decorate `send_email()` with:
     ```python
     @retry(
         stop=stop_after_attempt(3),
         wait=wait_random_exponential(multiplier=1, min=2, max=10),
         retry=retry_if_exception_type((httpx.TimeoutException, httpx.NetworkError, ConnectionError)),
         before_sleep=before_sleep_log(logger, logging.WARNING),
         reraise=True
     )
     ```
   - The method is async, so tenacity will handle it correctly (tenacity supports async)
   - Move the try/except inside send_email to be OUTSIDE the retry scope - the retry decorator wraps the method, so internal try/except that returns error dicts will prevent retries. Instead, for retryable errors (timeouts, network), raise the exception to trigger retry. For non-retryable errors (auth failures, 4xx responses), return the error dict.
   - Specifically: if `response.status_code >= 500`, raise an exception to trigger retry. If 4xx, return error dict (don't retry).

IMPORTANT: Use `import logging` for log level constants with `before_sleep_log`. The tenacity `before_sleep_log` expects a stdlib logger or structlog bound logger and a log level integer.

For structlog compatibility with tenacity's `before_sleep_log`, pass the structlog logger directly - structlog's bound loggers are compatible with tenacity's logging integration.

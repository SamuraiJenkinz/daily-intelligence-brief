2. Create `app/services/drift_monitor.py` with class `ClassificationDriftMonitor`:

   **Constructor:** `__init__(self, baseline_days: int = 14)`
   - Store baseline_days
   - Create structlog logger bound with `service="drift_monitor"`

   **Method `check_confidence_drift(self, db: Session, threshold: float = 0.05) -> dict`:**
   - Query baseline period: articles classified (baseline_days*2) to (baseline_days) days ago
   - Query recent period: articles classified in last 3 days
   - Extract priority field as a proxy for confidence (since Azure OpenAI structured outputs don't return explicit confidence scores). Map priority to numeric: Critical=4, High=3, Medium=2, Monitor=1
   - If insufficient data (baseline < 30 or recent < 10), return `{"drift_detected": False, "reason": "insufficient_data", ...}`
   - Perform Kolmogorov-Smirnov test: `ks_2samp(baseline_scores, recent_scores)`
   - Return dict with: `drift_detected`, `p_value`, `ks_statistic`, `baseline_mean`, `baseline_std`, `recent_mean`, `recent_std`, `baseline_count`, `recent_count`
   - Log result (warning if drift detected, info if passed)

   **Method `check_role_distribution_drift(self, db: Session, threshold: float = 0.05) -> dict`:**
   - Query baseline articles (same time windows as above)
   - Query recent articles
   - Count role assignment frequencies for each of 4 roles: Brokers, Leadership, Compliance, Underwriting
   - Parse roles from JSON string using `json.loads(article.roles)`
   - Normalize baseline distribution and compute expected frequencies for recent data
   - Perform chi-square test: `chisquare(observed_recent, expected_from_baseline)`
   - Handle edge case: if any expected frequency is 0, set minimum to 0.1 to avoid division by zero
   - Return dict with: `drift_detected`, `p_value`, `chi2_statistic`, `baseline_distribution`, `recent_distribution`
   - Log result

   **Method `check_category_distribution_drift(self, db: Session, threshold: float = 0.05) -> dict`:**
   - Same pattern as role distribution but for the `category` field
   - Categories: M&A, Regulatory, Loss Event, Financial Results, Market Trends, Product Launch, Executive Change, Other
   - This catches prompt drift where categories become skewed

   **Method `run_all_checks(self, db: Session) -> dict`:**
   - Call all three check methods
   - Return combined results:
     ```python
     {
         "timestamp": datetime.utcnow().isoformat(),
         "any_drift_detected": any of the three detected drift,
         "confidence_drift": {...},
         "role_distribution_drift": {...},
         "category_distribution_drift": {...}
     }
     ```
   - Log summary

   **Method `format_drift_alert_email(self, results: dict) -> str`:**
   - Takes results from `run_all_checks()`
   - Format as HTML email with:
     - Header: "Classification Drift Alert"
     - For each drift type with drift_detected=True, show a section with:
       - Test name and p-value
       - Baseline vs recent statistics
       - Recommendation (e.g., "Review classification prompt" or "Check recent article quality")
     - For insufficient data, show informational note
   - Inline CSS for email compatibility

   IMPORTANT about the priority-as-confidence proxy: Since Azure OpenAI structured outputs with `response_format=ArticleClassification` don't return a separate confidence score, we use the priority distribution as a proxy. A shift in priority distribution (e.g., suddenly everything is "High") indicates classification behavior change.

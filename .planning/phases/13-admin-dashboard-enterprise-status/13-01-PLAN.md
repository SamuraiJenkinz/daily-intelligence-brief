**In app/routers/admin.py:**

1. Add import for ApiEvent and ApiEventType at the top:
   ```python
   from app.models.api_event import ApiEvent, ApiEventType
   ```

2. Add `_get_enterprise_api_status(db)` helper function (place before `get_admin_dashboard`). This queries the `api_events` table for the most recent event per `api_name` and derives status:
   - api_names to query: `["auth", "news", "equity", "email"]` (verified from codebase grep — these are the exact strings used in token_manager.py, factiva.py, equity.py, enterprise_emailer.py)
   - For each api_name, get most recent `ApiEvent` ordered by `timestamp DESC`, `.first()`
   - If no event: `status="unknown"`, `last_checked=None`, `reason=None`
   - If `latest.success == True`: `status="healthy"`
   - If `latest.success == False`: check if `latest.event_type` is in `{ApiEventType.NEWS_FALLBACK, ApiEventType.EQUITY_FALLBACK, ApiEventType.EMAIL_FALLBACK}` — if yes, `status="degraded"` (service worked via fallback); otherwise `status="offline"`
   - `last_checked` = `latest.timestamp.strftime("%Y-%m-%d %H:%M")` (no "UTC" suffix — timestamps are local)
   - `reason` = `latest.detail[:100]` if `latest.detail` else `None`
   - Return `list[dict]` with keys: `api_name`, `display_name`, `status`, `last_checked`, `reason`
   - `display_name` mapping: `auth` -> "Authentication", `news` -> "News (Factiva)", `equity` -> "Equity Prices", `email` -> "Email Delivery"

3. Add `_get_fallback_events(db, limit=20)` helper function:
   - Query `ApiEvent` where `event_type IN (NEWS_FALLBACK, EQUITY_FALLBACK, EMAIL_FALLBACK, TOKEN_FAILED)`
   - Order by `timestamp DESC`, limit to `limit`
   - Return list of dicts: `timestamp` (formatted string), `api_name`, `event_type` (human-readable: replace underscores with spaces, title case), `reason` (detail truncated to 100 chars)

4. Update `get_admin_dashboard()`:
   - After existing queries (runs, etc.), call `enterprise_status = _get_enterprise_api_status(db)` and `fallback_events = _get_fallback_events(db)`
   - Add `active_nav='dashboard'` to the `template.render()` call (currently missing — causes sidebar highlight bug)
   - Add `enterprise_status=enterprise_status` and `fallback_events=fallback_events` to the `template.render()` call

**In app/templates/admin/dashboard.html:**

5. Add Enterprise API Status panel BETWEEN the Page Header row and the Summary Cards row. Use a full-width card with a 4-column responsive grid inside:
   - Card header: `<i class="bi bi-shield-check"></i> Enterprise API Status` with `<small class="text-muted fw-normal ms-2">Updated on each pipeline run</small>`
   - Inside card-body, use `<div class="row g-3">` with one `col-md-3` per API
   - Each API shows: status icon (check-circle-fill/exclamation-triangle-fill/x-circle-fill/question-circle in success/warning/danger/secondary color), display_name bold, status badge (bg-success "Healthy", bg-warning text-dark "Degraded", bg-danger "Offline", bg-secondary "Unknown"), last_checked small muted, and reason text-danger small when present
   - When no events recorded: show "No events recorded" in muted text

6. Add Fallback Event Log card AFTER the Recent Pipeline Runs card. This is a new `<div class="row">` section:
   - Card header: `<i class="bi bi-exclamation-triangle"></i> Fallback Event Log` with `<small class="text-muted fw-normal ms-2">Last 20 events</small>`
   - If `fallback_events` is non-empty: render a `table table-striped table-hover` with columns: Timestamp, API, Event Type, Reason
   - API column shows the `api_name` capitalized
   - Event Type column shows human-readable event type
   - Reason column shows truncated detail, or "-" if none
   - If `fallback_events` is empty: show info alert "No fallback events recorded. Enterprise APIs have not triggered any fallbacks yet."

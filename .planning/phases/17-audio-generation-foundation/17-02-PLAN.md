  <action>
    Create `app/services/audio_generator.py` with an `AudioBriefingService` class that orchestrates the complete audio briefing pipeline.

    **Project root constant:**
    - Define PROJECT_ROOT the same way as pipeline.py: `os.path.dirname(os.path.dirname(os.path.dirname(os.path.abspath(__file__))))`
    - Define AUDIO_DIR: `os.path.join(PROJECT_ROOT, "data", "audio")` (matching `data/reports/` convention, NOT `output/`)

    **Class initialization:**
    - Import and instantiate ScriptGenerator and TextPreprocessor
    - Initialize a SEPARATE Azure OpenAI client for TTS (TTS may use a different deployment than GPT-4o)
    - Follow the same Azure OpenAI client initialization pattern as reporter.py/classifier.py (handle corporate proxy endpoint)
    - Store TTS-specific settings: model="tts-1-hd", voice="nova", response_format="mp3", speed=1.0
    - Add a settings property for configurable voice (read from settings, default "nova")
    - If Azure OpenAI not configured, set self.tts_client = None

    **Core method: `generate_briefing(role: str, articles: list[dict], report_date: datetime) -> dict`**
    This method runs the full pipeline for a single role:

    1. **Idempotent check:** Call `_should_generate(role, date_str)`. If file exists and is valid (>100KB), return early with `{"generated": False, "reason": "already_exists", ...}`
    2. **Script generation:** Call `self.script_generator.generate_script(role, articles, report_date)` to get raw script
    3. **Text preprocessing:** Call `self.text_preprocessor.preprocess(script)` to normalize for speech
    4. **Word count validation:** Count words in preprocessed script. Log warning if outside 250-600 range (generous bounds)
    5. **TTS conversion:** Call `self._convert_to_audio(preprocessed_script, output_path)` to create MP3
    6. **Return metadata:** path, size_bytes, size_mb, word_count, role, date, voice, model, generated=True

    **TTS conversion method: `_convert_to_audio(script: str, output_path: Path) -> dict`**
    - If self.tts_client is None, raise RuntimeError("Azure OpenAI TTS not configured")
    - Call `self.tts_client.audio.speech.create(model=self.model, voice=self.voice, input=script, response_format="mp3", speed=1.0)`
    - Write to a TEMP file first (`output_path.with_suffix('.tmp')`) then rename to final path (atomic write)
    - Use @retry decorator: stop_after_attempt(3), wait_random_exponential(multiplier=1, min=2, max=15), retry on APIError, RateLimitError, APIConnectionError, APITimeoutError
    - Return file metadata: path, size_bytes, size_mb, voice, model

    **Idempotent check: `_should_generate(role: str, date_str: str) -> bool`**
    - Build expected path: `data/audio/{date_str}/{role}.mp3`
    - If file exists and size > 100_000 bytes (100KB minimum for valid 2-min audio), return False
    - If file exists but too small, log warning about corruption and delete it, return True
    - If file doesn't exist, return True

    **Batch method: `generate_all_briefings(articles: list[dict], report_date: datetime) -> dict`**
    - Iterate over ["brokers", "leadership", "compliance", "underwriting"]
    - For each role, filter articles using the same logic as reporter.py's filter_articles_by_role (articles where role is in article['roles'])
    - Call generate_briefing for each role
    - Return dict: {"results": [per-role results], "total_generated": N, "total_skipped": N, "total_failed": N}
    - Wrap each role in try/except so one role's failure doesn't block others
    - Log summary with total generated, skipped, and failed counts

    **File naming convention (from CONTEXT.md):**
    - Directory: `data/audio/YYYY-MM-DD/`
    - File: `{role}.mp3` (lowercase role name)
    - Example: `data/audio/2026-02-27/brokers.mp3`
    - Create directory with os.makedirs(exist_ok=True)

    **Logging:**
    - Use structlog throughout
    - Log key events: script_generated, script_preprocessed, audio_generated, audio_skipped, audio_failed
    - Include role, date, word_count, file_size in log entries
    - Log TTS API call duration for performance monitoring

    IMPORTANT: Do NOT import or integrate with pipeline.py in this plan. Pipeline integration is Phase 19.
    IMPORTANT: Keep TTS client initialization separate from GPT-4o client (they may use different deployments/endpoints).
    IMPORTANT: The articles parameter uses the SAME dict structure as reporter.py's _prepare_articles output.
  </action>

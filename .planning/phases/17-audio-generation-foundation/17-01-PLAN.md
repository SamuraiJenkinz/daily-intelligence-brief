  <action>
    1. Add `num2words>=0.5.13` to requirements.txt (after tenacity line).
    2. Run `pip install num2words` to install the dependency.
    3. Create `app/services/text_preprocessor.py` with a `TextPreprocessor` class containing a `preprocess(script: str) -> str` method that applies these transformations in order:

    **Currency normalization (_normalize_currency):**
    - `$X.XB` / `$X.X billion` -> "X point X billion dollars" using num2words
    - `$X.XM` / `$X.X million` -> "X point X million dollars" using num2words
    - `$X.XK` / `$X.X thousand` -> "X point X thousand dollars" using num2words
    - `$X.X` (plain dollar amounts) -> "X point X dollars" using num2words
    - Handle variations: "$1.2B", "$1.2 billion", "$150M", "$25K", "$500"
    - Pattern order matters: match B/M/K suffixed amounts BEFORE plain dollar amounts

    **Percentage normalization (_normalize_percentages):**
    - `15.3%` -> "fifteen point three percent"
    - `7%` -> "seven percent"
    - Use num2words for integer parts, handle decimals with "point" separator

    **Abbreviation expansion (_normalize_abbreviations):**
    - Build a PRONUNCIATION_DICT at module level with insurance/financial abbreviations:
      - Spell-out abbreviations: LLC, CEO, CFO, CIO, COO, IPO, ESG, CFD, ABS, ILS, D&O, E&O, FCA, NAIC, APRA, PRA, IFRS, GAAP
      - Expand abbreviations: M&A -> "M and A", Q1-Q4 -> "Q one" through "Q four", H1/H2 -> "H one"/"H two", YoY -> "year over year", QoQ -> "quarter over quarter", bp/bps -> "basis points"
    - Use word-boundary regex (\b) to avoid partial matches

    **Ticker symbol normalization (_normalize_tickers):**
    - Pattern `(AAPL)` parenthesized tickers -> spell out letters "A A P L"
    - Only match 2-5 uppercase letter sequences in parentheses

    **Company name pronunciation (_normalize_company_names):**
    - Build a COMPANY_PRONUNCIATIONS dict for commonly mispronounced insurance/reinsurance companies:
      - "Aon" -> "A-on" (prevent "ay-on")
      - "Zurich" -> "Zuurik" (insurance pronunciation)
      - "Munich Re" -> "Myoonik Re"
      - "SCOR" -> "S C O R"
      - "Tokio Marine" -> "Tokyo Marine"
      - Add 10-15 commonly mispronounced names
    - Apply as regex word-boundary replacements

    Use structlog for logging. Log the number of transformations applied per category.

    IMPORTANT: Do NOT use SSML markup anywhere. OpenAI TTS does not support it. ALL pronunciation control is via text preprocessing.
  </action>

  <action>
    Create `app/services/script_generator.py` with a `ScriptGenerator` class following the established Azure OpenAI client pattern from classifier.py and reporter.py.

    **Class initialization:**
    - Accept no arguments (load from settings like reporter.py does)
    - Initialize Azure OpenAI client using the SAME pattern as reporter.py __init__ (handle corporate proxy endpoint with '/deployments/' and standard endpoint)
    - Store self.client and self.deployment
    - If Azure OpenAI not configured, set self.client = None

    **Core method: `generate_script(role: str, articles: list[dict], report_date: datetime) -> str`**
    - If self.client is None, return a fallback text: "Audio briefing unavailable. Azure OpenAI not configured."
    - If no articles provided, return a short "no articles" script: "Good morning, this is your Marsh {role} intelligence brief for {date}. There are no significant developments to report today. That's your {role} brief for today. Stay informed."
    - Build system prompt and user prompt (see below)
    - Call self.client.chat.completions.create() with model=self.deployment, temperature=0.7, max_tokens=800
    - Return the generated script text
    - Wrap in try/except, log errors, return fallback on failure

    **System prompt (_build_system_prompt):**
    Follow the research document's GPT-4o Podcast Script Generation Prompt pattern exactly:
    - Narrator persona for Marsh {role}
    - Audio character: Female, authoritative, Bloomberg/Reuters style
    - Script structure: Branded intro -> priority-ordered content -> sign-off
    - Branded intro: "Good morning, this is your Marsh {role} intelligence brief for {date}..."
    - Sign-off: "That's your {role} brief for today. Stay informed."
    - Source attribution: "Reuters reports...", "According to Financial Times..."
    - Synthesized overview narration (group by theme, not per-article)
    - 300-540 words target (2-5 minute audio at 150 wpm)
    - Write for listening: short sentences, contractions OK, conversational
    - Natural language for ALL numbers (write out figures)
    - Role-specific tone guidance per CONTEXT.md decisions

    **User prompt (_build_user_prompt):**
    - Accept articles as list[dict] with keys: title, summary, source_name, priority, category, sentiment
    - Group articles by priority tier (Critical, High, Medium)
    - Format each article as: "- {title} ({source_name}): {summary}"
    - Include article count per tier
    - Articles come pre-filtered for the role (caller's responsibility)

    **Retry logic:**
    - Use @retry decorator from tenacity (same pattern as classifier.py):
      stop_after_attempt(3), wait_random_exponential(multiplier=1, min=2, max=15),
      retry on ConnectionError, TimeoutError, APITimeoutError, APIConnectionError

    Use structlog for logging. Log: role, article_count, word_count of generated script.

    IMPORTANT: The articles parameter uses the SAME dict structure as reporter.py's _prepare_articles output (keys: title, description, source_name, priority, summary, sentiment, category, roles, etc.). Reuse that shape, not a custom one.

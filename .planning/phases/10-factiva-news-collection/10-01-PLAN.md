  <name>Task 2: FactivaCollector class — API client with search, article fetch, and normalization</name>
  <files>

  <action>
1. Create `app/collectors/__init__.py` — empty or with `from app.collectors.factiva import FactivaCollector` and `__all__ = ["FactivaCollector"]`.

2. Create `app/collectors/factiva.py` with the `FactivaCollector` class. Follow the httpx + tenacity + structlog patterns from `app/auth/token_manager.py`. Key design:

   **Class attributes:**
   - `BASE_SEARCH_PATH = "/coreapi/recent-news/v1/search"`
   - `BASE_ARTICLE_PATH = "/coreapi/recent-news/v1/article"`
   - `SOURCE_LABEL = "Factiva"`
   - `MAX_ARTICLES = 100` — hard cap to avoid excessive API calls

   **`__init__(self)`:**
   - Read `settings = get_settings()`
   - Store `self.base_url = settings.mmc_api_base_url.rstrip("/")` and `self.api_key = settings.mmc_api_key`
   - Bind structlog logger: `self.logger = structlog.get_logger(__name__).bind(service="factiva_collector")`

   **`is_configured(self) -> bool`:**
   - Return `bool(self.base_url and self.api_key)`

   **`collect(self, query_params: dict, run_id: Optional[int] = None) -> List[Dict[str, Any]]`:**
   - Build search params from `query_params` dict (keys: industry_codes, company_codes, keywords, page_size)
   - Convert industry_codes/company_codes from comma-separated to API format
   - Set `fromDate` = yesterday (UTC), `toDate` = today (UTC) for 24h window
   - Set `sortBy="date"`, `sortOrder="desc"`, `deduplication="similar"`
   - Call `_search(params)` to get search results
   - Extract article list from response (handle `data` or `articles` key — check research for exact response structure)
   - If response includes `pagination.links.pageSize100` URL and article count < MAX_ARTICLES, follow that link to get up to 100 results in one call (use the full URL directly)
   - For each article in search results (up to MAX_ARTICLES): call `_fetch_article(articleId)` to get plaintext body. Use a try/except per article — if individual fetch fails, fall back to snippet from search result. Log warning but continue.
   - Normalize each article via `_normalize_article(search_item, article_body)` into standard dict schema
   - Record API event via `_record_event()` using `ApiEventType.NEWS_FETCH` on success
   - Return list of normalized article dicts
   - On any exception during search (not individual article fetch): log error, record `NEWS_FETCH` event as failure, re-raise (caller handles fallback)

   **`_build_headers(self) -> dict`:**
   - Return `{"X-Api-Key": self.api_key, "Accept": "application/json"}`
   - Do NOT include Content-Type (GET requests don't need it)
   - Do NOT call TokenManager — Factiva uses X-Api-Key only

   **`_search(self, params: dict) -> dict`:**
   - Decorated with `@retry(stop=stop_after_attempt(2), wait=wait_exponential(multiplier=1, min=2, max=10), retry=retry_if_exception_type((httpx.TimeoutException, httpx.ConnectError)))`
   - Use `httpx.Client(timeout=30.0)` as context manager
   - GET `{self.base_url}{self.BASE_SEARCH_PATH}` with params and headers
   - Call `response.raise_for_status()`
   - Return `response.json()`

   **`_fetch_article(self, article_id: str) -> dict`:**
   - Same retry decorator as `_search`
   - GET `{self.base_url}{self.BASE_ARTICLE_PATH}/{article_id}` with headers
   - Return `response.json()`
   - Returns empty dict on non-retryable errors (4xx) — log warning

   **`_normalize_article(self, search_item: dict, article_body: dict) -> dict`:**
   - Map Factiva API response to standard schema:
     - `title`: `search_item.get("headline", "").strip()`
     - `description`: `article_body.get("plaintext") or search_item.get("snippet") or ""`
     - `url`: `article_body.get("links", {}).get("self") or search_item.get("links", {}).get("self") or ""`
     - `published_at`: Convert `search_item.get("publicationTimestampInMilliseconds")` from epoch ms to datetime
     - `source_name`: `"Factiva"` (maps to news_articles.source_name)
     - `collector_source`: `"Factiva"` (new field for source attribution)
   - Return the dict

   **`_record_event(self, event_type: ApiEventType, success: bool, detail: str, run_id: Optional[int] = None) -> None`:**
   - Follow exact pattern from `token_manager.py._record_event()`
   - Create isolated DB session via `SessionLocal()`
   - Create `ApiEvent(event_type=event_type, api_name="news", success=success, detail=detail, run_id=run_id)`
   - Commit and close in try/except/finally — swallow errors to protect caller flow
   - Use `detail[:500]` to truncate long error messages

   **Imports:**
   - `httpx`, `structlog`, `tenacity` (retry, stop_after_attempt, wait_exponential, retry_if_exception_type)
   - `datetime`, `timedelta` from datetime
   - `List, Dict, Any, Optional` from typing
   - `get_settings` from app.config
   - `SessionLocal` from app.database
   - `ApiEvent, ApiEventType` from app.models.api_event

   **Anti-patterns to avoid:**
   - Do NOT inherit from `NewsSource` ABC — it requires ApifyClient
   - Do NOT use `httpx.AsyncClient` — match the sync pattern used by `ApifyCollector.collect_from_sources()`
   - Do NOT call `TokenManager.get_token()` — Factiva uses X-Api-Key, not JWT
   - Do NOT construct pagination params manually — use opaque pageSize links from response
   - Do NOT trust `pagination.totalResults` for loop control — use actual article count
  </action>

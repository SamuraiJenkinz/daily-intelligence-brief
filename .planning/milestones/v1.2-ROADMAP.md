# Roadmap: MDInsights v1.2 Factiva Knowledge Integration

## Overview

Replace the Apify web scraping collection layer with BrasilIntel's proven FactivaCollector, making Factiva/Dow Jones the sole news source via MMC Core API. This milestone ports the mature 456-line FactivaCollector (pagination, body-fetch fallback, retry, event tracking), removes all Apify infrastructure, simplifies the pipeline to a single collection path, and updates the dashboard for the new Factiva-only architecture.

## Phase Details

### Phase 14: FactivaCollector Port

**Goal**: Port BrasilIntel's mature FactivaCollector to replace Apify collection layer

**Depends on**: Phase 13 (v1.1 complete)

**Requirements**: COLL-01, COLL-02, COLL-03, COLL-04, COLL-05, COLL-06, COLL-07

**Success Criteria** (what must be TRUE when phase completes):
1. FactivaCollector integrates with MMC Core API search endpoint using configurable query parameters from FactivaConfig
2. FactivaCollector fetches full article body for each article, falling back gracefully to snippet if body fetch returns 4xx
3. FactivaCollector handles pagination automatically via pageSize100 links to collect up to 100 articles per run
4. All API interactions (search, body fetch, pagination) are recorded as ApiEvent records visible in admin dashboard
5. FactivaCollector normalizes Factiva response fields to MDInsights NewsArticle schema with correct source attribution
6. FactivaConfig is seeded with English insurance/reinsurance industry codes and keywords appropriate for MDInsights audience
7. Retry logic with exponential backoff (2 attempts, 2-10s) handles transient network failures gracefully

**Plans**: 2 plans

Plans:
- [x] 14-01-PLAN.md -- FactivaConfig model: add date_range_hours column, update startup migration and seed data
- [x] 14-02-PLAN.md -- FactivaCollector: port 3 bug fixes + 2 improvements from BrasilIntel, wire pipeline

### Phase 15: Pipeline Simplification & Cleanup

**Goal**: Simplify pipeline to Factiva-only collection path and remove all Apify infrastructure

**Depends on**: Phase 14 (FactivaCollector operational)

**Requirements**: PIPE-01, PIPE-02, PIPE-03, CLEAN-01, CLEAN-02, CLEAN-03, CLEAN-04, CLEAN-05

**Success Criteria** (what must be TRUE when phase completes):
1. Pipeline orchestrator uses FactivaCollector as sole collection path with no fallback to Apify or RSS
2. Semantic deduplication (sentence-transformers) and URL deduplication continue to work with Factiva-only collection
3. ApifyCollector class and all Apify source implementations (artemis.py, business_insurance.py, etc.) are deleted from codebase
4. apify-client and feedparser dependencies removed from requirements.txt
5. APIFY_TOKEN and all Apify-related settings removed from config.py and .env.example
6. No references to Apify fallback logic remain in pipeline orchestrator or service layer
7. Dead source implementation files in app/services/sources/* are removed (only base.py retained for future extensibility)

**Plans**: 3 plans

Plans:
- [ ] 15-01-PLAN.md -- Refactor pipeline to Factiva-only collection, extract article storage, remove ApifyCollector from entry points
- [ ] 15-02-PLAN.md -- Delete ApifyCollector class, Apify source files, and update scripts
- [ ] 15-03-PLAN.md -- Remove Apify dependencies, config, and sweep stale references

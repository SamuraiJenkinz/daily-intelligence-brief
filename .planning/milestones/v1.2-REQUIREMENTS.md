# Requirements: MDInsights v1.2 Factiva Knowledge Integration

**Defined:** 2026-02-26
**Core Value:** Each audience at Marsh receives only the intelligence relevant to their decisions, priority-ranked and AI-summarised, delivered daily with zero manual effort.

## v1.2 Requirements

Port BrasilIntel's mature FactivaCollector to replace the Apify web scraping layer. Factiva/Dow Jones becomes the sole news source via MMC Core API.

### Collection

- [x] **COLL-01**: FactivaCollector integrates with MMC Core API search endpoint with configurable query parameters (industry codes, company codes, keywords, date range, page size)
- [x] **COLL-02**: FactivaCollector fetches full article body via individual article endpoint, falling back to snippet if body fetch fails (4xx graceful degradation)
- [x] **COLL-03**: FactivaCollector handles pagination via pageSize100 links for extended result sets (up to 100 articles)
- [x] **COLL-04**: FactivaCollector uses tenacity retry with exponential backoff for timeout/connection errors (2 attempts, 2-10s backoff)
- [x] **COLL-05**: FactivaCollector records all API interactions as ApiEvent records for dashboard visibility
- [x] **COLL-06**: FactivaCollector normalizes Factiva response fields to MDInsights NewsArticle schema (title, description, url, published_at, source_name, collector_source)
- [x] **COLL-07**: FactivaConfig seeded with English insurance/reinsurance industry codes and keywords appropriate for MDInsights' audience

### Pipeline

- [x] **PIPE-01**: Pipeline orchestrator uses Factiva as sole collection path with no Apify fallback chain
- [x] **PIPE-02**: Semantic deduplication (sentence-transformers) runs on collected articles before storage
- [x] **PIPE-03**: URL deduplication prevents duplicate articles across pipeline runs

### Cleanup

- [x] **CLEAN-01**: ApifyCollector class and all Apify source implementations removed
- [x] **CLEAN-02**: apify-client and feedparser dependencies removed from requirements.txt
- [x] **CLEAN-03**: APIFY_TOKEN and Apify-related settings removed from config
- [x] **CLEAN-04**: Apify fallback logic removed from pipeline orchestrator
- [x] **CLEAN-05**: Dead source implementation files removed (app/services/sources/*)

### Dashboard

- [x] **DASH-01**: Health monitoring reflects Factiva-only collection architecture
- [x] **DASH-02**: Source badges and collection indicators updated for single-source model
- [x] **DASH-03**: Fallback event display updated (no more Apify fallback references)

### Config

- [x] **CFG-01**: .env.example updated to remove Apify variables and document Factiva-only setup
- [x] **CFG-02**: FactivaConfig admin UI reflects its role as sole collection configuration

## Future Requirements

Deferred to later milestones:

- **DATA-01**: Integrate coreapi-data endpoint for additional data enrichment
- **MULTI-01**: Support multiple collection sources (pluggable collector architecture)
- **ALERT-01**: Real-time critical alerts for breaking news

## Out of Scope

| Feature | Reason |
|---------|--------|
| Multiple collection sources | v1.2 simplifies to Factiva-only; source management UI retained for future |
| RSS feed collection | Removed with Apify layer; Factiva provides comprehensive coverage |
| Apify web scraping | Replaced by enterprise Factiva feed |
| New collection source types | Defer pluggable architecture to future milestone |
| BrasilIntel insurer matching | Domain-specific to BrasilIntel; MDInsights uses role-based classification |

# Milestone v2.0: Audio Intelligence Briefings

**Status:** SHIPPED 2026-02-27
**Phases:** 17-20
**Total Plans:** 11

## Overview

Add per-role podcast-style audio briefings to the daily intelligence pipeline, delivered as MP3 attachments and streaming links alongside existing HTML emails. AI-generated scripts via GPT-4o, converted to audio via Azure OpenAI TTS (with ElevenLabs failover), integrated into the daily pipeline with parallel processing and graceful degradation.

## Phases

### Phase 17: Audio Generation Foundation

**Goal**: System generates 2-5 minute per-role podcast-style audio briefings from classified articles with natural narration and proper pronunciation.
**Depends on**: None (foundational phase)
**Plans**: 3 plans

Plans:
- [x] 17-01-PLAN.md -- Text preprocessor and script generator services
- [x] 17-02-PLAN.md -- Audio generator service with TTS conversion and CLI runner
- [x] 17-03-PLAN.md -- End-to-end verification and human audio quality check (checkpoint deferred)

**Details:**
- TextPreprocessor normalizes financial figures, percentages, abbreviations, tickers, and company names for natural speech
- ScriptGenerator creates 300-540 word podcast-style scripts using GPT-4o with branded intro/sign-off and role-specific tone
- AudioBriefingService chains ScriptGenerator -> TextPreprocessor -> Azure OpenAI TTS to produce MP3 files
- Idempotent generation with atomic file writes (temp + rename pattern)
- Standalone CLI script for manual audio testing
- Validation script for programmatic audio pipeline checks

**Requirements:**
- SCRPT-01: Podcast-style narration script per role via GPT-4o
- SCRPT-02: Branded intro and sign-off
- SCRPT-03: Priority-ordered content (Critical / High / Medium)
- SCRPT-04: Text preprocessing for natural speech
- AUDIO-01: Azure OpenAI TTS (tts-1-hd model) as primary provider
- AUDIO-04: Consistent professional voice across all roles
- AUDIO-05: 2-5 minute duration per briefing

### Phase 18: TTS Provider Resilience

**Goal**: System maintains audio generation reliability through provider abstraction and automatic failover when primary TTS provider fails.
**Depends on**: Phase 17
**Plans**: 2 plans

Plans:
- [x] 18-01-PLAN.md -- TTS provider abstraction layer with Azure and ElevenLabs implementations
- [x] 18-02-PLAN.md -- AudioBriefingService failover integration with api_events logging and test script

**Details:**
- TTSProvider ABC (Strategy pattern) with synthesize() interface contract
- AzureTTSProvider and ElevenLabsTTSProvider implementations with atomic file writes
- Common TTSError exception for unified failover handling
- ElevenLabs SDK (v2.36.1) for fallback provider
- Automatic failover: try primary -> catch TTSError -> try fallback
- Cost alert on ElevenLabs fallback (20x more expensive than Azure)
- TTS_SUCCESS and TTS_FALLBACK event logging to api_events

**Requirements:**
- AUDIO-02: ElevenLabs fallback when Azure TTS unavailable
- AUDIO-03: TTS provider abstraction with consistent interface

### Phase 19: Pipeline Integration & Delivery

**Goal**: Audio briefings are generated automatically during daily pipeline execution and delivered via email attachment with streaming link, with email delivery guaranteed even when audio fails.
**Depends on**: Phase 18
**Plans**: 3 plans

Plans:
- [x] 19-01-PLAN.md -- Parallel audio generation in pipeline (Step 5c) and admin streaming endpoint
- [x] 19-02-PLAN.md -- Email services accept optional MP3 audio attachment (Graph + Enterprise)
- [x] 19-03-PLAN.md -- Wire audio through pipeline to email delivery with template streaming links

**Details:**
- Step 5c: Parallel audio generation for all 4 roles via asyncio.gather (~5-8s wall clock)
- Sync audio service wrapped in run_in_executor for async pipeline
- return_exceptions=True for per-role graceful degradation
- GET /admin/audio/{role}/{date} streaming endpoint with path traversal prevention
- Base64-encoded MP3 attachments in both Graph and Enterprise email services
- 3MB size limit with warning logs for oversized files
- Conditional audio section in email template with streaming link
- HTML entities for emoji (maximum email client compatibility)

**Requirements:**
- DLVR-01: MP3 audio file attached to role-based daily email
- DLVR-02: Streaming link in email to play audio in-browser
- OPS-01: Audio generation failure never blocks HTML email delivery
- OPS-02: Audio generation runs in parallel for all 4 roles

## Milestone Summary

**Key Decisions:**
- Azure OpenAI TTS (tts-1-hd) as primary provider, ElevenLabs as fallback (20x cost difference)
- Per-role audio (not combined) matching core value proposition
- All pronunciation control via text preprocessing (OpenAI TTS does not support SSML)
- Strategy pattern for TTS provider abstraction (ABC with unified TTSError)
- Parallel audio generation via asyncio.gather with return_exceptions=True
- Admin dashboard serves streaming audio using existing FastAPI server
- Filesystem storage for MP3 files (better streaming than DB BLOBs)
- Atomic file writes (temp + rename) in all TTS providers

**Issues Resolved:**
- Windows console encoding issue with emoji (replaced with ASCII-safe indicators)
- FastAPI route ordering conflict between audio and archive endpoints
- Circular import prevention via lazy import of audio service in pipeline

**Issues Deferred:**
- Human audio verification pending Azure OpenAI TTS credentials
- ElevenLabs failover untested with real provider credentials
- Enterprise email FIELD_ATTACHMENTS name inferred (validate on deployment)
- Email client compatibility testing (Outlook, Gmail, Apple Mail)
- TTS cost dashboard untested with real api_events data

**Technical Debt Incurred:**
- 8 deferred items pending Azure OpenAI TTS credential configuration
- 4 legacy items carried from v1.x (DB compatibility)
